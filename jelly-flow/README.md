# Jelly Flow · 软糖分流

面向英语玩家的 H5 解谜小游戏。采用 TypeScript + Canvas 2D，桌面和手机共用同一套规则与关卡。运行时无第三方依赖、外部字体或素材请求。

本目录由上一级 `game_project` Git 仓库统一管理。请在工作目录根目录查看和提交变更，不要在 `jelly-flow` 内初始化独立仓库。

## 开始运行

安装 Node.js 24 或更新版本后，在本目录执行：

```sh
npm ci
npm run build
npm run dev
```

打开 http://localhost:4173 。手机和电脑连接同一局域网时，可打开终端中提示的局域网地址，将占位符替换为电脑的局域网 IP。改完源代码需要重新执行 `npm run build`，再刷新页面；开发服务器不自动编译。

```sh
npm run check  # TypeScript 检查
npm test       # 规则、存档、控制器回归测试
```

`dist/` 是独立静态发布包，可放在支持 ES modules 的 HTTP/HTTPS 静态服务器上。不要直接双击 HTML 以 file:// 方式运行。

## 玩法和操作

- 点击软糖槽或其下方编号按钮，释放最前面连续同色的一组软糖。
- 软糖自动进入第一个尚未装满的同色杯子。杯子装满后，新杯子接替。
- 暂时没有匹配杯子的软糖进入 6 格等待区；有匹配杯子出现时自动收集。超过 6 格则失败。
- 所有软糖收集完成即过关，没有倒计时。
- 电脑可用数字键 1–6 释放，Z 撤销。手机使用点击，页面支持纵向滑动。
- Undo 撤销、Restart 重开、A little hint 提示、Levels 选关；失败后也可关闭结果弹窗并撤销。
- 无提示或撤销通关获 3 星，使用 1–2 次辅助获 2 星，更多辅助获 1 星。重开重置本次辅助次数。

## 已实现范围

20 个关卡由易到难分为入门、杯子接替、等待区规划和混合挑战。第 1–7 关 4 条队列，第 8–13 关 5 条，第 14–20 关 6 条；第 6 关开始加入第四种颜色。每关包含已回放验证的通关路径。难度曲线仍需玩家试玩校准。

包含解锁、星级、本地进度和未完成对局恢复，合成音效及静音设置，连锁提示、飞行软糖动画、减少动态效果偏好适配、重复输入保护和存储失败降级。存档仅保存在当前浏览器，不跨设备同步。

提示只返回验证过的可通关路线。偏离已有路线时有搜索时间与节点上限；没有及时找到路径会建议撤销，不会猜一个动作。

## 文件结构

| 文件 | 用途 |
| --- | --- |
| `src/core.ts` | 与浏览器无关的确定性规则、胜负判定、提示搜索 |
| `src/levels.ts` | 20 关数据与通关路径 |
| `src/renderer.ts` | Canvas 布局、软糖绘制、点击映射、动画 |
| `src/app.ts` | 交互控制、关卡流程、结果弹窗、星级 |
| `src/storage.ts` | 存档验证与 localStorage 降级 |
| `src/audio.ts` | 首次交互后启用的合成音效 |
| `index.html` / `styles.css` | 英文界面、桌面与移动布局 |
| `tests/` | 自动化测试 |
| `QA.md` | 已执行检查与验证边界 |
| `scripts/generate-levels.mjs` | 离线关卡生成工具；不会在游戏运行时执行 |

## TikTok 接入边界

当前交付是可独立运行的 H5 试玩版本，尚未接入 TikTok Mini Games SDK、账号、广告、平台存储或上线审核。H5 发布成功不代表已能直接作为 TikTok 内小游戏上线。下一阶段需结合获准使用的平台接入方式实现渲染与平台适配，纯规则和关卡数据可继续复用。

未接入广告、支付、云端排行榜或远程行为分析。控制器预留了内存事件记录位置，当前不上传任何游戏事件。后续建议先安排英语玩家试玩，观察首次理解、关卡失败与继续玩的意愿，再调整节奏、关卡和反馈。

发布使用 Sites 私有试玩站点，保持创建时的访问范围。正式测试前仍需补充 Android Chrome、iPhone Safari 和目标 TikTok 容器的真机检查。
