# 网页战斗运行层验证

日期：2026-10-23。对象：`../web/engine.js`，输入为 APK 静态恢复的 `../web/data/mechanics.json`。这是独立编写的 JavaScript 战斗重构，没有执行原 APK、原生库或原游戏 Lua，也没有调用游戏远程服务。

**当前可以证明：首关在原资源下存在可获胜的操作策略；18 关能启动模拟；全部静态出兵、已补入的首领和路径连接数据可运行。不能据此证明 18 关都已被玩家通关，或证明战斗与原游戏等价。** 原引擎恢复失败的独立证据见 `engine-feasibility.md`。

## 已恢复的基础规则

- 使用原始初始金币、20 点关卡生命、普通难度敌人生命/物理护甲/魔抗/速度/金币/普攻数值。支持读取 easy、normal、hard、impossible 四档原数值；默认测试 normal。
- 四种基础塔保留 1–4 级原价格、攻击范围、伤害上下限与攻击间隔，遵守关卡锁定等级。第 1 关允许四种基础塔，但最多 1 级。
- 箭塔价格 70/100/150/230，兵营 70/110/160/220，法师塔 100/150/210/280，炮塔 110/170/240/310。升级价格是该次升级的价格，不是累计价格。
- 杰拉尔德默认 1 级：220 生命、0.05 护甲、10–14 物理伤害、2 秒普攻间隔、速度 55、30 秒复活。没有添加测试用生命、伤害或金币倍率。
- 兵营生成 3 名守军，1 级生命 40、护甲 0.1、伤害 2–4、1 秒普攻间隔、12 秒复活；其他等级使用原数组。每名守军一次只锁定一个敌人，多名守军可以共同攻击同一敌人。原 `all/components.lua:456` 中 `enemy.max_blockers` 默认 nil。
- 火雨 60 秒冷却，3 颗陨石，每颗 30–45 真实伤害、60 半径；援军 15 秒冷却，2 名、12 秒存在时间、40 生命、2–4 伤害。投射物的视觉轨迹和延迟由网页运行层实现。
- 首波开始前按实际投入全额退款，开战后按投入的 60% 四舍五入退款；依据 `all/components.lua:430`、`all/systems.lua:1408`。第 2 关赠送的 1 级法师塔初始投入记为 0，后续付费升级计入投入。障碍清理费用单独扣除，依据原 terrain 价格 60/100/120，不计入塔退款。
- 提前开波奖励按剩余秒数四舍五入，每秒 1 金币；依据 `kr6/game_settings.lua:3–4`。重复点击不能重复领取。
- 伤害区分物理护甲、魔抗、爆炸对一半护甲的计算和真实伤害；按 `all/utils.lua:1226–1268` 的敌人/守军取整方式实现基础分支。

箭塔多射手数量不乘算伤害。对未能完整反编译的 `scripts_game.lua`，单独静态恢复了射手控制函数，并检查原行 19079–19092 的字节码：基础攻击共享一次 cooldown，随后轮换 `shooter_idx`，仅触发一个射手。证据保存在 `engine-gameplay-archer.json`。完整函数恢复失败仍如实保留，未把异常占位文本当成可执行原逻辑。

## 路径、波次与首领

将 Boss 手动组的 423 个静态支援出兵按组顺序连接，并补入由关卡 Lua 创建的 9 个首领实体。因此界面显示的总波数在第 8、10、11、13、15 关增加 1 波，在第 18 关增加 2 波。未静默跳过 Boss 后直接判胜；最后首领仍存活时不会胜利。

## 真实资源下的首关胜利

测试脚本只通过 `build`、`moveHero`、`callWave`、`cast`、`update` 操作，不修改金币、生命、攻击、敌人生命或波次。使用固定随机种子 703。

1. 用初始 175 金币，在 3 号位 `(580,415)`、5 号位 `(817,415)` 各建 1 级箭塔；杰拉尔德移到 `(565,356)`；开始首波。
2. 钱够时按 2、1、4、10、6 号位顺序补 1 级箭塔。首关不升级。
3. 每约 2 秒观察一次战场，在 x 330–980、y 150–650 的敌人中寻找半径 60 范围最密集的一组；至少 3 人且火雨可用时投放火雨，援军可用时部署在该组附近道路。
4. 若当前敌人已清空且处于波次等待期，提前开波。

上述是原坐标，y 轴朝上；画布内屏幕 y = 768 − 原 y。最终测试结果：**243.57 秒，5 波结束，16 生命、60 击杀、19 金币，胜利**。投入 490，击杀收入 321，提前开波收入 13；`175 + 321 + 13 − 490 = 19`，经济完全平衡。逐条操作及时间戳见 `engine-gameplay-test-results.json`。

相同默认配置不进行建造、走位或施法时，首关在 123.92 秒、第 3 波失败。其他 17 关也分别完成从启动至无操作失败的模拟，没有崩溃、NaN 或负金币。**后者是失败路径和运行稳定性测试，不是各关通关或平衡性证明。**

## 回归测试与可复现证据

从项目根目录执行：

```sh
node --test target/xinqicheng/tests/engine.test.mjs
```

11 项测试全部通过，包含：恢复数值核对；首关真实策略胜利；18 关无操作失败；暂停冻结队列/计时/投射物/冷却；建造/升级/出售/障碍清理/赠送塔与等级锁经济；提前开波奖励防重复；护甲类型；单兵拦截与多人围攻；技能数量/冷却/寿命；守军与英雄复活；全量运输探针；Boss 存活阻止提前胜利。

7728 个运输探针覆盖 417 条路径/子线路，以及 6879 普通出兵、423 手动支援、9 首领实体。每个探针检查初始数值有限、连接链正确且恰好到达一个最终出口。这是对运输原语的独立测试，允许漏怪，没有给予额外生命或金币，也不将探针中的状态称为玩家胜利。Boss 判胜门控使用独立合成关卡测试，不能解释为击败了原 Boss。

测试自动生成 `engine-gameplay-test-results.json`，保存各项检查、每关无操作结果、首关完整操作日志和经济账。浏览器画面、触控和自适应布局验证属于主任务的 UI 测试，未混入上述纯 Node 测试结论。

## 尚未等价恢复的规则

- 四种基础塔以外的 11 种塔，以及全部塔的独立技能、终极技能、成长/天赋/跨局升级树。
- 杰拉尔德之外的英雄；英雄经验与升级、被动、天赋和终极技能。当前默认杰拉尔德维持 1 级，只有原始普攻、移动、回血和复活。
- 敌人的特殊施法、回复、死亡后召唤、分裂、状态免疫细节、偷金币等逻辑；当前保留基础属性、普攻和路径移动。`DAMAGE_INSTAKILL`、`DAMAGE_EAT` 等特殊分支也未完整恢复。
- **335 条普通波和 37 条 Boss 手动波的 `event` 场景事件只保留记录，没有执行行为。** 其中包括额外敌人出兵，例如蜘蛛卵/垂降、召唤法师、沼泽怪物、树人和恶魔召唤，不只是装饰动画。现有 7302 个普通/手动静态出兵数量不包含这些事件生成的敌人，不能称为全量敌人复现。
- 原脚本中除 `all_enemies_died` 外的剧情等待信号、循环手动组和机关状态机；部分时序基于静态恢复的时间线，而非原协程执行。
- 原首关教程的 4 名教程敌人及脚本引导由网页提示替代。英雄、援军与火雨从开始可用，未保留原教程的分段解锁过程。
- 地形导航、动画攻击帧、投射物预测、碰撞与距离模型经过简化；范围采用圆形，单位移动采用直接追踪与回归集结点。回血有 3 秒脱战延迟，属于网页重构选择，不能视为已逐帧验证的原规则。
- 完整关卡平衡、全部 18 关玩家通关、困难/不可能难度通关未验证。当前已验证首关策略可赢，不通过增加金币、生命或伤害来掩盖后期内容缺口。

这些限制也通过 `Game.limitations` 和按关的 `Game.notices` 提供给开发/诊断层。UI 公共方法包括 `sellValue`、`clearCost`、`clearBlocked`、`maxTowerLevel`、`setPaused`、`setSpeed`，操作失败说明位于 `lastError`；`totalWaves` 包含新增首领波，`spellStats` 提供冷却/援军持续时间。原四塔 key 和 atlas 标识保持不变。
