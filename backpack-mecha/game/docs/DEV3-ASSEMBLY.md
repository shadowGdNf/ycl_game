# dev.3 装配与成型诊断

日期：2026-10-27。构建版本：`0.2.0-dev.3`；战斗/经济规则：`0.1.0`。本批完成 D3-1、D3-2 的核心开发，D3-3 设备基线待补齐。没有修改价格、掉率、伤害、Boss 血量或美术资源，也未更新线上 Pages。

## 玩家可见的变化

- 首次休整显示“选择免费线圈 → 放在兼容武器旁 → 检查连接并出击”；完成后显示当前增益，略过后不再重复提示。
- 选中支持件显示当前等级的收益和具体状态：备件未生效、没有武器、标签不兼容、连接位已满、没有共边、尚未选择连接、电力超限或连接生效。原因复用正式连接校验。
- 铆钉枪与增幅线圈显示基准单发伤害 `8 → 9.6`，明确只计这一连接，不含护甲、暴击和其他加成。其他支持显示当前等级的数值与触发条件；商店显示购买所得 I 级的连接收益。
- 局间最多给两条基于现有装备的建议，例如未连接支持、潮湿缺电伤或油污缺引燃。
- 备件可直接拖入背包，也保留点选放置。拖动使用指针 ID 和捕获；无效落点保留原装备和资源。撤销会同步旋转方向，拖入失败的提示不会被随后生成的点击事件清除。
- 沿用原存档版本和教程完成字段；收益提示不改变规则或随机流。

## 诊断方法与结果

保留历史 `qa/natural-probe.json` / `qa/natural-probe-runs.json.gz`。新测试使用相同的六路线、各十种子、拾荒者、难度 0、普通路线、每商店最多两次刷新和 10Hz 几何避险输入。仍按原时序升级、维修并跳过事件。

原策略的 60 局在胜负、装备、统计、战斗时间、核心成型场次和每场起止快照上与历史记录完全一致。两组各 60 局均通关，合计 1,440 场战斗与 1,440 次十秒存档恢复比较。这些是无渲染机器策略结果，不是玩家胜率、完整体验时间或设备性能。

扩展策略允许先出售再购买、最多移除两件非核心模块，并尝试重新布局。已有核心受到保护，缺失核心额外获得 100 点策略偏好。每次搜索最多检查 48 个移除组合、8 次重新布局；候选布局须转成正式购买、出售、移入备件、放置和连接操作，并从原状态成功重放，才报告“找到方案”。

| 路线 | 原策略成型局数 | 扩展策略成型局数 |
|---|---:|---:|
| 潮湿电链 | 9/10 | 9/10 |
| 燃油连爆 | 7/10 | 10/10 |
| 穿甲齐射 | 4/10 | 8/10 |
| 堡垒震荡 | 2/10 | 9/10 |
| 无人机编队 | 8/10 | 9/10 |
| 冰霜回弹 | 10/10 | 10/10 |

成型表示至少一场开战时全部核心已装备并通过合法装配校验。对照同时改变了搜索与偏好，不能把变化全部归因于多件替换或重新布局。同一种子也不保证后续供货相同：选择变化会改变随机流消耗与后续战斗结果。

每个缺失核心决策保存当时规则快照、供货来源、现金、约束、原策略是否能给出方案和扩展搜索结果，以 SHA-256 键去重。原策略记录 291 个决策，扩展策略 227 个，均未达到容量上限。原策略中有 62 个决策找到了其旧搜索未给出的合法购买方案；这是决策数，不是 62 局。两组共 370 个方案已再次通过正式接口重放。

原策略仍有 57 个、扩展策略有 52 个决策在搜索上限内未找到方案，标为 `search-exhausted`，不称为无解。绝对资金不足仅在“当前碎片加出售全部库存所得仍不足”时标记为 `insufficient-total-scrap`；本批自然样本没有该结果，自动测试用明确标注的库存夹具验证了它。奖励供货分别记录 21 / 18 次，但没有搜索其替换路径，保留“只观察到供货”的限制。

### 两个可追溯案例

1. **穿甲齐射，`natural-v02-02`，第 4 场商店，U05 瞄准镜。** 当时碎片约 69.69，主要限制为电力。出售 I 级 S01 增幅线圈后可以直接装入瞄准镜；原策略对瞄准镜的评分低于线圈，未接受这一转换。扩展策略该局首次完整成型在第 10 场。决策键：`190590784f4492f1b3c01a602001021238e5893c4090e9f775816460400a4277`。
2. **堡垒震荡，`natural-v02-02`，第 3 场商店，W09 圆锯盘。** 当时碎片约 58.13，主要限制为电力。出售 S08 汲能整流器和 W01 铆钉枪后，可以在零基坐标 `(3,1)`、旋转 `1` 直接购买装入。原策略只尝试单件替换；扩展策略该局第 3 场成型。完整键、出售等级和逐步操作见对照报告中对应案例。

这些反例足以证明旧策略遗漏了一些合法转型，不证明所有未成型局都属于策略问题，也不证明出售这些装备对真人生存最优。本轮保留原有数值，后续再结合输入模型和真人观察决定平衡调整。

### 浏览器实际操作

环境为 macOS 的 Codex 内置浏览器，独立 `localhost:4194` 来源。使用公开按钮、键盘、指针和刷新，没有注入装备、资源或胜负。

1. 完成实际首场 40 秒战斗，进入首次休整。点选免费线圈并放入：电力 `2 → 3`、占格 `2 → 4`，显示连接生效与 `8 → 9.6`。
2. 旋转线圈使其失去共边，显示“只碰角不会连接”；撤销恢复。再次旋转能正确断连，验证方向同步修复。拖动到另一合法位置连接继续有效。
3. 刷新继续第 2 场，首次连接完成状态保留。速射齿轮预览显示 I 级攻速 `+15%`；点击直接购买后，显示碎片 `75 → 57`、电力 `3 → 4`、占格 `4 → 5`，与预览一致。
4. 在 390×844 CSS 视口检查中文购买弹窗与英文三步引导；页面 `clientWidth` 和 `scrollWidth` 均为 390。打开色彩辅助与减少动态效果后，步骤、连接符号和收益仍可辨。
5. 略过引导、刷新、继续，教程不再出现，齿轮与碎片保持。维修后购买冷冻喷头到备件架，直接拖入成功：电力 `4 → 6`、占格 `5 → 7`。撤销还原；拖到占用格显示持续错误提示，资源和装备未变；再次拖入合法格成功。
6. 携四件模块实际进入第 2 场、移动后暂停。保存回站、刷新、继续，仍以暂停状态恢复且四件模块一致。没有把这段记录称为完成首章或完整远征。
7. 页面 warning/error 查询为空；结束时已重置临时视口，保留暂停试玩页。
