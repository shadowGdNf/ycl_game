# v0.2.0-dev.4 开发计划：战斗动作与网页流程验证

计划日期：2026-10-27。状态：**动作核心已实现，独立浏览器及设备验收待补齐**。基线为 `0.2.0-dev.3`，规则版本 `0.1.0`。下文保留开工时的范围与验收要求；当前运行版本为 dev.4，实际结果见 [DEV4-MOTION.md](DEV4-MOTION.md) 和 `qa/dev4-check.json`。

## 版本目标

玩家能从敌人的姿态和地面提示判断“准备攻击、伤害生效、硬直或弱点窗口”，并能在网页上完成装配、十二场远征、结算和再次开局。沿用 A 方案风格化金属素材，先完成三个动作样板，再扩展六 Boss 的关键反馈。

把原定 dev.5 的**第一条完整网页通关记录**提前到本版，同时补独立桌面 Chrome / Safari 验证。dev.5 继续负责多机体、多路线、设备性能与成长平衡，避免两版重复计算同一项工作。

本版以表现和流程完善为主：不预设新增章节、机体、模块或经济数值调整。若验证发现规则缺陷，单独记录触发条件、修复范围和对照结果，不把行为变化藏在动画改造里。

## 已有证据与本次核对

- dev.3 记录为 73 项自动测试通过、120 局机器对照、370 个合法购买方案重放；网页实际操作到第二场出击、暂停和刷新恢复。证据见 [dev.3 记录](DEV3-ASSEMBLY.md)及 `qa/dev3-check.json`。
- 当前构建仍为 dev.3；本次核对 `qa/dev3-check.json` 中列出的源码哈希全部一致。这里只核对已有证据，没有重新执行上述测试，也没有把机器模拟算成网页通关。
- 当前敌人渲染主要为整张图的轻微起伏和倾斜；危险区域已有独立上层绘制。已有状态图标和通用命中/死亡效果可继续使用，不重复建设。
- 战斗内部已有预警区域、来源实体、延迟、冲锋、硬直、弱点时间与母舰侧舱暴露状态，但 `EnemyView` / `ZoneView` 尚未完整表达动作语义。
- `frozen` 同时用于寒冷冻结、撞墙停止和 Boss 失衡；当前渲染把非零值都画成冰冻。这是本版优先修正的显示问题，规则中的停顿时长先保持不变。
- 五张图集、86 个采样区域、网页目录 9,654,710 字节（约 9.21 MiB）作为本版资源基线。

合计约 **6–8 人日**，另留 **1–2 人日**修复缓冲。按一名主开发、美术按需支持估算，不代表 AI 执行时长或日历承诺；设备取得和外部试玩等待另计。原动作批次为 4–6 人日，本次增加了动作语义梳理与提前执行的完整网页验收。

顺序为 D4-00 → D4-01 → D4-02 → D4-03 → D4-04。每个样板实现后即做对应网页验证，不能积累到最后才打开浏览器。复用既定 A 风格，样板内部验收通过即可继续扩展。

### D4-01：三个动作样板

| 对象 | 玩家应看到的变化 | 与现有规则的对应 |
|---|---|---|
| E05 自爆电池 | 停步蓄能、外壳/能量圈逐步增强、爆炸与消失；提前击杀能取消蓄能表现 | 读取现有 0.8 秒预警、半径 70 的区域与实体存活状态；不能靠视觉计时自行爆炸 |
| E12 重型清扫车 | 蓄力压低、明确冲锋方向、冲锋中的运动反馈、撞墙后的机械停顿 | 读取 1 秒预警、1.5 秒冲锋及碰撞后 1.5 秒停止；地面宽度与实际碰撞语义分别核对 |
| B1A 压路王 | 蓄力、推进、撞墙硬直；扇形重击和落点攻击可辨；二阶段连冲有独立前摇 | 读取首冲 1 秒预警/1.4 秒动作和撞墙后 2 秒停止；延迟中的第二冲不得提前显示成正在造成伤害 |

以上数值来自当前实现，是同步参照，不是本版新调参。三者均检查：准备期间被击杀、冻结/失衡中断、暂停、继续、刷新恢复，以及攻击发生在屏幕边缘的情况。

优先用已有素材的局部遮罩、部件位移、轮廓和方向提示完成动作。需要独立轮廓时再补透明部件；不能把固定透视整图大幅旋转当作完整转身。先验证样板可读，再决定确需新增的图集区域，不预先生成整套动画帧。

### D4-02：六 Boss 的关键反馈

B1A 已由样板覆盖，继续补齐其余五个 Boss。每个只围绕影响玩家判断的关键动作，不要求为所有招式制作完整逐帧动画。

| Boss | 本版关键反馈 | 容易误导的边界 |
|---|---|---|
| B1B 起重机 | 牵引方向、摆锤准备/扫过、二阶段反向扫击 | 牵引范围与伤害范围区分；摆锤表现跟随实际扫掠角度 |
| B2A 熔炉蟹 | 炉门蓄热、喷火方向、喷火后弱点窗口 | 只有 `vulnerableUntil` 有效时显示弱点，不把所有后摇都称为易伤 |
| B2B 磁轨双子 | 两端蓄能、连线生效、齐射方向 | 端点与当前世界中的攻击计划一致；不擅自把固定伤害线改成跟随身体的线 |
| B3A 回收者 | 激光蓄能与扫向、扩散环、安全间隙、阶段切换 | 使用区域当前角度和内外半径；保留环内安全区，不用装饰光覆盖它 |
| B3B 回收母舰 | 轰炸准备、侧舱打开/暴露、弹幕发射 | 侧舱能否成为目标与 `exposed` 一致；一阶段关闭部件的展示不能暗示可以命中 |

按实际可达阶段覆盖：B1A/B1B/B2B 各两阶段，B2A/B3A/B3B 各三阶段；不把测试中手工设置的不可达阶段计作内容覆盖。高难度额外攻击若出现在验证矩阵中，单列难度与触发条件。

统一信息层的完成条件：

- 地面准备区、正在生效的危险、无伤害的牵引/传送带有形状、线型或符号区别；不能只改颜色。
- 冰冻、撞墙硬直、Boss 失衡分别表达。已有旧存档无法确定原因时使用中性的“暂时无法行动”反馈，不能强行画成冰冻。
- 潮湿、燃烧、冰冻和电链在战斗实际缩放下仍能区分。伤害数字和友方效果不遮住危险边界。
- 减少动态效果模式保留方向、阶段、危险边界与弱点提示，用稳定姿态和轮廓替代震动、快速闪烁与拖影。

## 实现边界

主要文件为 `src/renderer.ts`、`src/types.ts`、`src/art.ts`。确需提供动作来源、控制状态原因或弱点时，才补 `src/combat.ts` 的只读展示数据；涉及持久状态时同步处理 `src/storage.ts`。

1. 优先从已有 `ZoneState.sourceId`、延迟、活动状态、冲锋和弱点时间派生动作信息，集中为每个实体生成一次，避免每个绘制步骤反复遍历所有区域。展示字段不参与命中、AI、奖励或胜负计算。
2. 动作使用战斗逻辑时间。暂停不能继续蓄力，低帧率不能改变预警长度；刷新恢复后从已有状态恢复姿态，不依赖“必须看过上一帧”的动画队列。
3. 控制状态原因若必须持久保存，采用可缺省字段并校验范围；旧存档缺失时安全降级。本版目标是保持有效 dev.3 续局，不能通过丢弃旧存档来通过验证。
4. 命中/死亡表现可使用有容量和生命周期限制的渲染缓存。死亡部件仅作显示，不能继续碰撞、再次发奖或产生伤害；回站、新局和时间回退清空旧缓存。
5. 复用现有事件和特效容量限制，不增加每帧、每敌人的离屏 Canvas 分配。视觉变化不消耗游戏随机流。
6. 新增图集区域时，同步更新区域元数据、素材来源和验证脚本。当前包体脚本固定检查 86 个区域，不能只删掉这个断言；改为校验已登记清单、必要 ID 和实际期望数量。
7. 开发预览明确显示“场景夹具”，使用独立来源或禁用持久写入。测试文件与调试入口不能进入正式网页包。

## 验收与性能

**规则与状态：** 类型检查和现有 73 项回归保持通过；新增针对动作阶段边界、多个延迟攻击、控制状态原因、旧存档缺字段以及渲染不修改规则状态的测试。测试应验证可观察行为，不断言无意义的测试数量或私有函数结构。

纯渲染改动运行相应状态/场景回归即可。若触及战斗状态导出、事件或存档，则增加相同输入下的规则状态对照与恢复检查，至少复跑原策略六路线各十种子；对照 dev.3 的胜负、伤害、资源、装备和逐场结果。新增展示字段可单独核对，不能以扩大忽略字段范围来掩盖规则变化。实际修改战斗规则时再追加 Boss 探针并明确规则版本。

**可读性：** 三样板和六 Boss 关键动作在桌面与窄屏均有准备、生效、恢复的证据；动画方向和边界与实际规则一致；受控状态不会被误画成另一机制。没有真人观察前，只报告工程检查通过，不宣称玩家理解率提高。

**包体与性能：** 建议本版网页目录目标不超过 **11 MiB**，从 dev.3 的 9.21 MiB 比较；仓库现有 20 MiB 上限仍作为兜底检查，不能把它当成新的增长预算。先用现有部件实现，只有视觉收益明确时增加图集。

选择同一浏览器、设备、视口和固定战斗场景，对 dev.3 / dev.4 分别预热后采集三段各 60 秒的前台样本，涵盖第三章密集敌人、Boss 和多区域叠加。记录帧间隔分布、超过 50ms 的比例、最长停顿及渲染耗时；新动作的渲染耗时 p95 相对基线增长超过 15% 时先检查缓存、遮罩和装饰效果。这是开发回退线，不是已测结果或手机流畅保证。

精确 p95 来自有上限的原始采样；现有七档帧间隔直方图只能报告所在区间。无渲染模拟速度、平均帧率或一张窄屏截图不能替代性能记录。完整手机 20 分钟运行、发热和内存增长留在 dev.5。
