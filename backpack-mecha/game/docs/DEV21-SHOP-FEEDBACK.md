# dev.21：商店状态修复与装配决策反馈

版本 `0.2.0-dev.21`，规则版本仍为 `0.2.6`。本地源码及 `dist/` 已更新，未推送或部署。

## 商店报错的原因与修复

第 2 场结束后进入第 3 场的战利品阶段，`run.phase` 为 `reward`，但 `run.shop` 仍保留上一场的四个商品。点击「先整理背包」后，旧界面会把这些商品显示成可购买状态；交易层要求 `prep`，因此购买和购买合成都会报「当前不在商店」。事件奖励、连续奖励和 Boss 扩容阶段也存在界面与状态不一致的风险。

界面与交易统一使用 `shopAccess()` 判断。待领奖、扩容、协议选择时，显示明确的待办入口，隐藏旧商品、刷新、维修和锁定；完成全部待办后开放有效商店。旧存档恢复后同样适用。事件奖励完成后恢复同一商店，正常战后流程生成下一场商品；不跳过奖励，也不把上一场商品当成本场商品交易。整理背包和合成已有装备仍可在待领奖时使用。

购买动作增加状态防护；满备件的直接放置购买，只在确实可购买时进入放置模式，避免把其他失败原因误报为空间不足。

## 同步优化

- 首次连接的三步引导常驻装配页。连接状态、实际收益和详情入口保持可见；移除重复的「自动装入」按钮。
- 合成预览显示已装备武器数量、释放的格数与电力、同型号合计基础输出变化。两把普通铆钉枪合成一把精良时，显示 `2× → 1.35×（-32.5%）` 和输出下降提示；购买材料升级已装备武器则增加输出。比较只包含已装备数量与品质，不把配件、护甲或命中率估计成实战 DPS。
- 全部 18 种武器显示用途。商品提示与当前装备的互补关系；构筑方向列出缺失部件，支持件只有已装备且连接生效才计入完成。
- 商店提供上一场前三项伤害贡献、占比、主要威胁和应对建议。结算把内部敌人编号改为中文/英文名称，并记录实际造成伤害的攻击类型。旧存档缺少攻击明细时只显示已知信息。
- 宽度不超过 640、视口高度不超过 760 时，内容区可滚动、背包保持 210 像素高度、出战按钮固定；同一装配阶段重新渲染保留滚动位置。
- 自然局探针新增可选当前版本策略，覆盖 W13–W18、四机体 Q 技能、已获得的专精点与购买合成。历史策略入口保留；增加实际装备、主动技能触发和真正接通的核心组合记录。
