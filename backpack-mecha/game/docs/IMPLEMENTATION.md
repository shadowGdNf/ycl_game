# 实现与接口记录

版本0.1，2026-10-26。以原设计和开发计划为基线，主集成负责公共类型、目录导出、应用入口、存档和发布；并行工作分别负责战斗/关卡、装配/经济、素材/渲染。没有让渲染、碰撞和奖励各自维护第二套规则。

## 规则边界

- `newRun(chassis, mode, difficulty, seed)` 创建整局。机体/内容范围和难度门控在经济层再次校验。
- `validateLoadout(run)` 负责格位、数量、电力、唯一件、支持兼容性和邻接。编辑期间可暂时无武器或过载，但 `startWave` 会拒绝非法装配。
- `createBattle(run)` 复制合法开战状态，不在战斗中读取实时装配界面。
- `stepBattle(state,input,1/60)` 是唯一推进规则的入口。主循环把渲染帧累计为固定步长，单帧最多6步，卡顿时放慢游戏时间而不跳过伤害步骤。
- `battleResult` 输出统计增量、战利品和随机流；`resolveBattle` 校验同一场结算标记并统一处理奖励、战后恢复与下一阶段。
- `Renderer.draw(BattleView)` 只读数据；事件有唯一ID。预警与命中判定使用相同区域几何。暂停和死亡表现期间不推进规则。
- `saveGame` 先复制再串行写入，避免较旧的异步写入覆盖新交易。恢复验证内容ID和完整运行字段。

## 内容与随机

装备使用实例UID区分同名武器。旋转为0/1/2/3个顺时针90度；四角编号0左上、1右上、2左下、3右下。支持引用武器UID，视觉挂点按稳定UID分配，与背包格位无关。

随机流按shop/map/event/combat独立。创建遭遇、商店刷新、事件和暴击均可随快照恢复。普通战预算按20%/50%/30%时间段投放；安全出生预警、实体上限和公共寻路由遭遇系统维护。每章四个预制障碍模板，共十二个，Boss采用其专用场地。

难度使用最终累计倍率。难度4强化阶段每轮首招额外重复，预警、后摇和互斥仍由相同招式状态机处理。双子共用生命与单次区域攻击去重；母舰货舱使用同一生命组，曝光状态控制可命中部件。召唤和分裂子体不重复贡献预算碎片。

## 经济与流程

`prep → battle → reward/expansion/protocol → prep`；终局进入`won`或`lost`。领奖可关闭弹窗先腾空备件，必须完成待领奖流程才能出击。事件必须选择处理或离开。交易使用整局副本完成后提交，失败不扣钱、不消耗随机流。

出售撤销恢复该次出售和后续交易的完整快照，不能保留购买物后单独追回已售物；战斗开始清除撤销。背包编辑撤销在交易、领奖、事件、阶段结算后失效。待购商品同时绑定商店槽和模块ID，商店刷新、交易撤销等动作取消意向，避免错买。

两章试炼从`DEMO_IDS`选取24模块，敌人E01–E06，固定B1A/B2A。第一Boss后扩至23格、基础电力12、最高II级；wave8直接结算。协议排除无人机专属P05。三条合法测试构筑按399.4碎片基准检查，允许不同实际击杀/路线改变所得。
